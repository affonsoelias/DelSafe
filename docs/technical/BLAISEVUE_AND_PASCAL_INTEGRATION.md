# Native Integration Between DelSafe and BlaiseVue

> **How to use DelSafe's strict type system and ownership guarantees as the business-logic, state, and backend engine for BlaiseVue's reactive ecosystem.**

---

## 1. Overview and Motivation

**BlaiseVue** is a modern, reactive, component-oriented framework built on Free Pascal, designed for high-speed backend and frontend applications.

Integrating **DelSafe** with BlaiseVue gives developers:
1. **Zero Memory Leaks:** State logic, computation, and business rules are statically checked by DelSafe's *Borrow Checker* at compile time without hidden runtime overhead or GC pauses.
2. **Pattern Matching & Algebraic Data Types:** Expressive `Result<T, E>`, `Option<T>`, and exhaustive `match` handling without messy `try/except` boilerplate.
3. **Native Compilation Parity:** DelSafe transpiles directly into **clean, idiomatic Object Pascal Units**, compiled natively by Free Pascal in milliseconds without slow FFI bridges or DLL wrappers.

---

## 2. The Power of `--unit`: Structured Pascal Unit Emission

When invoked with `emit pascal --unit`, DelSafe generates a canonical **Object Pascal Unit** instead of a standalone `program`:

```bash
delsafec emit pascal src/UserStore.dels --unit
```

## 3. Consuming from BlaiseVue via `uses`

Inside your BlaiseVue component, controller, or HTTP server unit, simply add the generated unit to the `uses` clause:

```pascal
unit UserController;

{$mode objfpc}{$H+}

interface

uses
  SysUtils,
  BlaiseVue.Core,
  UserStore; // <-- Unit generated by DelSafe!

type
  TUserController = class(TBlaiseController)
  private
    FSession: TUserSession;
  public
    constructor Create; override;
    procedure HandleClick;
    function RenderView: string;
  end;

implementation

constructor TUserController.Create;
begin
  inherited Create;
  // Constructor generated by DelSafe:
  FSession := CreateUserSession('Carlos BlaiseVue');
end;

procedure TUserController.HandleClick;
begin
  // Leak-free mutable borrow:
  IncrementCounter(FSession, 1);
end;

function TUserController.RenderView: string;
begin
  Result := GetSessionReport(FSession);
end;

end.
```

## 4. Development Pipeline & Tooling

To keep BlaiseVue workflows instantaneous, the DelSafe CLI provides dedicated integration flags:

### 4.1 Custom Output Directory (`--out-dir`)
Write generated Pascal units directly into BlaiseVue's managed folder:
```bash
delsafec emit pascal src/UserStore.dels --unit --out-dir=./generated/blaisevue
```

### 4.2 Reactive Hot-Reload (`--watch`)
Keep the compiler watching for file saves and regenerate `.pas` units automatically:
```bash
delsafec emit pascal src/UserStore.dels --unit --watch
```
Live console output:
```text
========================================================
  DelSafe File Watcher (Hot-Reload / BlaiseVue Ready)
========================================================
Watching for changes in: "src/UserStore.dels"
Press Ctrl+C to stop.

[23:13:30] [WATCH] Change detected in "UserStore.dels"...
      [OK] File regenerated successfully!
```

### 4.3 Silent Mode for BlaiseVue CLI (`--silent`)
When BlaiseVue invokes `delsafec` in the background, pass `--silent` to receive only exit codes and errors:
```bash
delsafec emit pascal src/UserStore.dels --unit --out-dir=.blaisevue/generated --silent
```
On success, it exits cleanly with **code 0**. On type or borrow-checker failure, it returns **code 1** with formatted diagnostics.

## 5. Zephyr: BlaiseVue's Native Backend (`vendor/zephyr`)

**Zephyr** is BlaiseVue's high-performance native backend engine written in DelSafe, located directly under `vendor/zephyr` inside the BlaiseVue repository.

### 5.1 Key Features
1. **Simple & Declarative:** Express/FastAPI-style routing with typed handlers and request/response injection.
2. **Instant Serialization:** Leverages DelSafe's `[derive(JSON)]` metaprogramming to serialize domain records without boilerplate.
3. **Kernel-Level Performance:** Built directly over DelSafe's OS sockets (`std/net.dels`) with zero-copy borrow-checked buffers and cooperative `Task<T>` coroutines.

### 5.2 Dual Native Compilation (C or Pascal)
- **Production (C Binary via GCC):** Compiled with `--target=c -O3 -flto -s` for maximum request throughput and a minimal memory footprint (~20 KB to 50 KB).
- **Development (Pascal Binary via FPC):** Compiled with `--target=pascal` for rapid iteration, native FPC debugging, and seamless integration with Object Pascal units.

### 5.3 High-Reliability Security Architecture
- **Zero Memory Leaks & Zero Buffer Overflows:** The Borrow Checker ensures buffers and strings are never used after free or corrupted by data races.
- **Active DoS & Slowloris Protection:** Strict bounds on request headers/bodies (`MaxBodyBytes`, `MaxHeaderBytes`) and idle socket timeouts.
- **Type-Safe Input Sanitization:** Typed JSON deserialization rejects malformed payloads before reaching route handlers.
- **Built-In Security Headers & Rate Limiting:** Out-of-the-box defenses including HSTS, CSP, `X-Frame-Options`, and strict CORS policies.
